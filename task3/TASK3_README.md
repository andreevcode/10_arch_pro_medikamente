### 1. Классификация данных для защиты

Ниже данные платформы "Медикаменте" классифицированы по профилю риска, чувствительности и состоянию:
- **Класс 1: PHI.** Высший профиль риска. Включает диагнозы, направления, выписки, результаты анализов (PDF). Хранится в EMR DB и S3 Object Storage. Требует максимальной защиты как от внешних утечек, так и от внутренних инсайдеров.
- **Класс 2: PII.** Высокий профиль риска (например, ФИО, контакты, паспортные данные пациентов). Хранится строго изолированно в Patient DB.
- **Класс 3: Финансовые данные.** Средне-высокий профиль риска. Данные об оплатах, чеки. Хранятся в Payment DB и передаются в 1С.
- **Класс 4: Данные безопасности и Аудит.** Средний профиль риска. JWT-токены, учетные записи сотрудников (в Keycloak), а также неизменяемые логи доступа (в Audit DB / Elasticsearch).
- **Класс 5: Обезличенные и операционные данные.** Низкий профиль риска. Свободные слоты расписания, обезличенные витрины данных в Data Lake.

### 2. Базовые инструменты защиты
- **Data in Transit (в движении):**
  - **Внешний контур:** Использование TLS 1.3 на уровне API Gateway для всех клиентских приложений (Mobile App, Web Portal) и интеграций (Webhooks от лабораторий).
  - **Внутренний контур:** Внедрение Service Mesh (например, Istio) для обеспечения **mTLS (Mutual TLS)** между всеми микросервисами и базами данных. Никакого открытого HTTP-трафика внутри кластера.

- **Data at Rest (в покое):**
  - **Application-Level Encryption (ALE):** Основной паттерн для PII и PHI. Сервисы (`Patient Service`, `EMR Service`) на лету запрашивают Data Encryption Keys (DEK) из **HashiCorp Vault** и шифруют конкретные колонки (ФИО, диагноз) перед записью в PostgreSQL.
  - **Transparent Data Encryption (TDE):** Шифрование самих дисков/томов БД и S3-хранилища (SSE-KMS для MinIO) для защиты от физической кражи носителей или дампов.

### 3. Средства автоматизированного контроля
- **Data Discovery & Tagging:** Автоматизированные скрипты для регулярного сканирования файлового хранилища (S3) и баз данных на предмет незашифрованных PII (например, если врач случайно вписал ФИО в поле для комментариев). Метаданные передаются в **Data Catalog (Apache Atlas)**.
- **Audit & Anomaly Service:** Мониторинг логов доступа из API Gateway в реальном времени. Инструмент (Elastic Security) выявляет аномалии: например, массовую выгрузку медкарт одним сотрудником.
- **DLP (Data Loss Prevention):** `Lab Service` автоматически фильтрует исходящие заявки в лабораторию, пропуская только штрих-коды и отсекая любые текстовые поля с конфиденциальными данными.
